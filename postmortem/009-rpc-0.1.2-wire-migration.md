# 009 — Wire migration to the dsh 0.1.2-rc.1 RPC protocol

> **Status**: shipped.  The migration described here (dot→slash unary RPC,
> `/api/remote.mux` follow/core topology, `$events` waterfalls answered via
> `$events/result`, `workspace/follow` replacing `workspace.list`) is landed
> and documented under the `## 0.3.0 - Unreleased` "dsh 0.1.2 wire protocol
> migration" breaking change.  `docs/rpc.md` stays the wire reference; this
> record keeps the "why".

## Background

`docs/rpc.md` was rewritten (commit `adc2d4a`) to describe the dsh master /
0.1.2-rc.1 protocol face as the migration target.  The client still spoke the
removed legacy line (`adc2d4a` §0): dot-method unary RPC (`session.list`),
`POST /api/respond` client-response answering of `approval/requested` /
`question/requested` server-request frames, two WebSockets
(`/api/events.mux` per chat + `/api/events.host` for the list), and a
`session.history` HTTP bootstrap that the mux full-backlog replay had to be
dropped around.  The user's dsh server is already 0.1.2-rc.1 / master, so the
client must switch wholesale — no legacy compat layer (AGENTS: delete, don't
deprecate).  Browser-session auth was already landed (postmortem/008), so the
remaining work is the wire itself.

## Decision

Migrate the whole client to the protocol in `docs/rpc.md` in one epic, and
adopt this connection topology for `/api/remote.mux`:

- **Per-chat follow connection**: each chat buffer keeps its own
  `/api/remote.mux` socket (reusing the RFC 6455 layer unchanged) and opens
  exactly one logical stream `session/follow` (address `{kind:'session',
  sessionId}`).  The snapshot item seeds the transcript and sets the render
  anchor to the snapshot `cursor`; subsequent `event` items render live.
- **One global core connection**: `$events` + `session/control` +
  `workspace/follow` streams (all host-wide) live on a single connection
  opened by the session-list buffer (`*dsh-sessions*`,
  `dsh-emacs-session-mode`) and scoped to its lifecycle.  It replaces both
  `/api/events.host` and the per-chat `session/queue` / `session/projection` /
  approval+question mux frames.  Frames are routed by `sessionId` to live chat
  buffers via the global `dsh-emacs--chat-buffers` table; waterfalls arrive
  exactly once (one `$events` source), answered with the ready frame's
  `clientId` + the waterfall `eventId` via one-shot `POST /api/$events/result`
  (a `client-request` with `method: "$events/result"`).
- **`workspace/follow` on demand**: the list display opens a `workspace/follow`
  stream; the same endpoint (open → baseline → close) replaces the deleted
  `workspace.list` RPC as the manual/refresh path, so `dsh-emacs-list-workspaces`
  becomes "re-baseline".
- History: `session.history` (and the whole replay-drop + bounded-refetch
  hand-off machinery, plus the watchdog's history-probe RPC) is deleted.
  Opening a session is just opening the follow stream; snapshot `records`
  (`{type:'event'|'chunks'}`) are rendered with the existing anchor diff.
- Unary envelope: `payload` is always exactly `{args: {…}}`; each method
  endpoint is `<namespace>/<method>` and equals the envelope `method`.
  `session.prompt` gains the required client-made `requestId`.
- Queue mirror: `session/control` `baseline`/`queue` frames feed
  `dsh-emacs-queue-apply` unchanged in semantics; the "first frame of a
  generation seeds silently" rule replaces the old "first frame of a
  connection" seeding (the per-buffer mirror tracks the control generation,
  not a process object).
- Approvals/questions: answered via `$events/result` with `outcome.kind ∈
  result | next | rejected`; queue keys and dedup move from rpcId/approvalId
  to the waterfall `eventId`; the legacy "resolved" frames are replaced by
  the host `cancel` frame retiring by `eventId`.
- `session.models` (session-scoped catalog with a `current` field) becomes
  `session/modelCatalog` (session-agnostic, no `current`); the displayed
  "current" model now comes from projections (`modelSelection.lastUsed`) /
  `request/header` events instead of an RPC round trip.

## Why

- One socket per chat + one shared core keeps the buffer-scoped lifecycle
  machinery (reconnect timers, health check, watchdog, kill hooks) intact
  for the chat content path — the migration stays a frame-protocol swap
  rather than a state-machine rewrite.  The alternative — a single
  fully-shared mux with a stream table — was rejected: it would have forced
  every buffer-local reconnect/drop/seed decision into global ownership for
  no wire-protocol gain.
- `$events` and `session/control` are host-wide broadcasts; the protocol has
  no per-session queue/waterfall endpoint.  Opening them per chat would
  duplicate waterfalls (needing global dedup) and replay the whole-host
  control baseline into every socket, so they are centralised on one core
  connection.  The old list-scoped host stream was the natural owner and
  stayed the owner: dsh-emacs' entry point opens the session list, and chats
  are reached from it, so a chat is always backed by a live list buffer (and
  thus a live core connection).  Keeping the core connection list-scoped
  preserves the buffer-scoped lifecycle teardown (a chat whose list was
  killed still works, but the app expects the list open for the full
  control/waterfall surface — see Known limitations).
- Follow's bounded snapshot removes the reason the client ever dropped mux
  frames while loading history (the legacy replay could be 500k+ events) —
  the anchor gate plus `cursor` seeding now does the dedup that the
  drop-then-refetch loop existed for.
- Chunk-packed `chunks` records are only produced for *past*, completed
  content; live follow frames are never packed.  Completed runs always carry
  an `assistant/message` final event, which the initial-load path renders
  (it skips `assistant/chunk` anyway).  Skipping packed rows on seed render
  is therefore lossless for the windowed transcript model; no expansion
  machinery is needed for 0.1.2.

## Consequence

- The wire surface (`dsh-emacs.el` RPC layer and call sites,
  `dsh-emacs-events.el`, `dsh-emacs-queue.el`, protocol structs,
  renderers' history entry, tests in `test/dsh-test.el`, plus
  `docs/architecture.md`, `docs/model-picker.md`, README and CHANGELOG) is
  updated in one coherent release under the unreleased breaking-change
  banner; nothing speaks the legacy endpoints after the change.
- `dsh-emacs-list-sessions` still refreshes `session.list` (unchanged
  method), but workspace/archive state comes from `workspace/follow`
  baselines; the refresh-frame recording (`dsh-emacs-events--host-refresh-*`)
  is kept but its recorded frame kinds follow the new emits/frames.
- The queue mirror, mode-line ctx%, titles, run spinner, and interrupt paths
  keep their existing UI contracts; only their data source moves.
- Users of a server older than 0.1.2-rc.1 can no longer use the client — the
  upgrade is not backwards compatible by design (matching the removed server
  surface).

## Known limitations

- No transcript paging to older-than-window content: `session/page` is not
  wired into a UI (the snapshot's `hasMore` is available for a future
  "load earlier" affordance).
- `chunks` packed records in follow snapshots are not expanded; if a future
  feature renders a live in-progress run from a snapshot, expansion becomes
  necessary.  Compaction shadowing (`surfaceOp: replace` +
  `sourceEventSeqs`) is not yet handled either — both are dsh-web-parity
  work, not blockers for the 0.1.2 wire migration itself.
- The "current model" presentation depends on projection/header data instead
  of an explicit RPC; a brand-new blank session shows
  `dsh-emacs-default-model` until the first `request/header` lands.
- The core `$events`/`session/control` connection is list-buffer-scoped: a
  chat opened with no `*dsh-sessions*` buffer alive (or after its list was
  killed) receives its `session/follow` transcript but not the queue/waterfall
  /whole-host-projection surface until the session list is opened again.
  Normal usage (entry point opens the list; chats are opened from it) never
  hits this; it is a deliberate lifecycle simplification, not dsh-web-parity
  for exotic chat-only layouts.
